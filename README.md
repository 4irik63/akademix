# AkademiX Study — бот заказов

Готовая ветка оформления заказа на учебную работу: пользователь выбирает
тип работы, указывает предмет, срок и детали — бот сохраняет
заказ в базу SQLite, присваивает номер, назначает исполнителя (по кругу
между всеми администраторами) и уведомляет его. Клиент и назначенный
исполнитель могут переписываться прямо через бота.

## Структура проекта

- `config.py` — токен бота, ID админ-чата, путь к базе данных
- `database.py` — работа с SQLite (создание/получение заказов)
- `states.py` — шаги диалога (FSM)
- `keyboards.py` — инлайн-кнопки
- `handlers.py` — вся логика сценария заказа
- `main.py` — точка входа, запуск бота

## Установка

```bash
pip install -r requirements.txt
```

## Настройка

Задайте токен и ID администраторов через переменные окружения. Заказы
будут распределяться между админами по очереди (round-robin): первый
заказ — первому админу, второй — второму, третий — снова первому, и т.д.

```bash
export BOT_TOKEN="ваш_токен_от_BotFather"
export ADMIN_CHAT_IDS="111111111,222222222"
```

Можно указать любое количество админов через запятую — заказы будут
распределяться поровну между всеми перечисленными.

Свой Telegram ID можно узнать у бота **@userinfobot** — напишите ему
`/start`, он пришлёт ваш числовой ID. **Важно:** каждый администратор
должен сам написать вашему боту `/start` хотя бы один раз — иначе бот
не сможет написать ему первым (ограничение Telegram).

Если ADMIN_CHAT_IDS не задан, заказы всё равно будут сохраняться
в базу — просто уведомления не будут никому приходить.

## Запуск

```bash
python main.py
```

## Админ-панель

Команда `/admin` (доступна только тем, чьи ID указаны в `ADMIN_CHAT_IDS`)
открывает панель с фильтрами: 🆕 Новые, ⏳ В работе, ✅ Выполненные,
🗄 Архив, 📋 Все заказы. Оба администратора видят **все** заказы
независимо от того, кому конкретно заказ назначен.

Когда заказ отменяют, он автоматически уходит из раздела «Все заказы» —
там остаются только активные и выполненные. Посмотреть отменённые
можно отдельно через кнопку **🗄 Архив**.

По каждому заказу — карточка с кнопками:
- **▶️ Взять в работу** — статус меняется на «в работе»
- **✅ Готово** — заказ помечается выполненным
- **❌ Отменить** — заказ отменяется
- **💬 Чат с клиентом** — открывает чат с клиентом этого заказа

При смене статуса клиенту автоматически приходит уведомление
(«взят в работу» / «выполнен» / «отменён»).

## Чат клиент ↔ исполнитель

После того как заказ подтверждён и назначен исполнитель, и клиенту,
и исполнителю приходит кнопка **«💬 Чат по заказу»**. При нажатии бот
входит в режим пересылки: всё, что пишет один участник, автоматически
уходит другому с пометкой номера заказа. Выйти из чата — кнопкой
«Завершить чат» или командой `/endchat`.

Важно: чтобы бот мог написать участнику первым (переслать сообщение),
этот участник должен был хотя бы раз написать боту `/start`.

## Важно: обновление базы данных

Если вы уже запускали бота раньше со старой версией (где был вопрос про
объём работы), удалите старый файл базы — структура таблицы изменилась:

```bash
rm orders.db
```

Бот создаст новый файл автоматически при следующем запуске.

## Как расширить

- **Другой источник хранения** (ваш внешний API вместо SQLite): замените
  функции в `database.py` (`create_order`, `get_order`, `get_user_orders`)
  на HTTP-запросы к вашему API — сигнатуры функций менять не обязательно,
  остальной код (`handlers.py`) трогать не придётся.
- **Оплата**: после `confirm_order` можно добавить шаг с выставлением
  счёта через `bot.send_invoice` (Telegram Payments).
- **Файлы от клиента** (методичка, шаблон): добавить ещё один шаг State
  для приёма документа (`message.document`).
- **Панель администратора**: команда `/myorders` уже показывает каждому
  админу только назначенные ему заказы. Можно добавить кнопки смены
  статуса — использует уже готовую `update_order_status`.
- **Другое распределение** (например, по загруженности, а не по кругу):
  замените логику выбора `assigned_admin_id` в `handlers.py` —
  например, выбирать админа с наименьшим числом заказов в статусе
  `new`/`in_progress` через `get_admin_orders`.
